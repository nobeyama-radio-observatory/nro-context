# 聞き取りの記録の書き方

資産の台帳の値のうち、公開資料にないもの（保守の手間、担い手の数、更新の見込みなど）は、保守の担い手に聞き取って集めます。その記録の書き方の正本です（[0006](../decisions/0006-資産の情報を装置群ごとの運用リポジトリに置く.md)）。記録そのものは、各運用リポジトリの `interviews/` に置き、台帳の `sources` から問いを指します。

各運用リポジトリの `interviews/README.md` には、ここへのリンクだけを置きます。

## 書き方

- **1回の聞き取りを1ファイルにします。** 名前は `YYYY-MM-DD.md`。同じ日に2回あれば `YYYY-MM-DD-2.md` とします。
- **回答者が確認した要約を残します。** やり取りの書き起こしではありません。記録を公開する前に、回答者に中身を確かめてもらいます。回答者がプルリクエストを読めるときは、記録を取り込むプルリクエストの確認をもって回答者の確認とし、記録の冒頭の「回答者の確認」にそう書きます。本来の担当に代わって答えた記録（所長の叩き台など）は、本来の担当の確認が済むまで、冒頭にそのことを書いておきます。
- **回答者は役割で書きます。** 名前、連絡先、個人の評価は書きません。
- **事実と見立てを分けます。** 答えのうち見立て（「〜になりそう」「おそらく〜」）に当たるものには `（見立て）` と添えます。台帳に移すときは `（仮説）` を添えます。`maintenance.effort` のように値が決まった語に限られる項目では、値に添えられないので、`sources` に「（回答者の見立て）」と書きます。
- **公開できない話は書きません。** 制御の手順、接続先、ネットワーク構成、契約の中身が出たら、記録から外します。保守の支援の有無は書いてよく、契約の中身は書きません。
- **「分からない」も記録します。** 答えが「不明」だった問いも残します。台帳では `未記入` のままにします。
- **書いた後は直しません。** 答えが変わったら、新しい日付の記録を足します。台帳は新しい記録を出典にして直します。ただし、雛形の「台帳への反映」の表は、記録を公開した後に足したり直したりしてかまいません（問いと答えは変えません）。

台帳からは、`聞き取り2026-11-18 問3` のように日付と問いの番号で指します。台帳の冒頭の出典の略記に、`聞き取りYYYY-MM-DD 問N：interviews/YYYY-MM-DD.md の問N` と書いておきます。

## 雛形

```markdown
# 聞き取り YYYY-MM-DD

| 項目 | 内容 |
|---|---|
| 日付 | YYYY-MM-DD |
| 回答者 | 役割（例：分光計の保守の担当） |
| 聞き手 | 人か AI か（例：AI（Claude）が問いを作り、会話で聞き取った） |
| 回答者の確認 | 済（YYYY-MM-DD） |
| 対象 | 台帳の id |

## 問いと答え

### 問1 （対象の id）：問いの要約

答えの要約。見立てには（見立て）と添える。

## 台帳への反映

| 問い | 台帳の id と項目 | 反映した値 |
|---|---|---|
```

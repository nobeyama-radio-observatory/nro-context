## 背景

上流の問いの5回目の試行（2026-11-18-7）と、Q7 の事前の試行（2026-11-18-8）で、外から関わる人の問い（Q5、Q6、Q7）に共通する欠けが二つ見つかった。

- **問い合わせの窓口がどこにも記録されていない。** Q5 の要素 (8)(9)、Q6 の要素 (14)、Q7 の A7・B7 が、どれもこの欠けで止まっていた。
- **利用者と観測者向けの公開資料の所在が記録されていない。** 台帳の `docs` は「データシート」とだけ書かれ、該当するページを指していなかった。観測の手引き、運用のルール、トラブルシューティング、積分時間の見積もりの所在も、文脈基盤になかった。

0010 と 0011 は、観測所の公開資料が正本の情報は、正本の所在を示せれば満たしたとし、手順そのものを写すことは求めないと決めている。0011 は、窓口と所在を記録すれば Q7 が 17項目中 9 前後に上がると予測した。

2026-11-19 に観測所のウェブサイトを確かめたところ、観測準備の流れ、望遠鏡運用のルール（強風、降雪、地震の中断の基準と、終了時の手順）、積分時間の見積もり、受信機ごとの性能のページ、ヘルプデスクの経路がすでに公開されていた。トラブルシューティングのページも作られていたが、開くと 404 で、公開されていない。試行で「記録がない」とした事柄の多くは、一次資料にはあり、文脈基盤から指していないだけだった。

非公開の一覧には、観測者向けの非公開の手順書と連絡の一覧の行がなく、ほかの行の正本の場所も「（要確認）」が多かった。

## 決定

利用者と観測者が読む公開資料の所在と、問い合わせの窓口を、ハブの新しい場所 `users/` に索引する。あわせて、台帳の `docs` に該当するページの URL を書き、非公開の一覧に観測者向けの資料の行を足す。

- **ハブの `users/README.md`：** 装置をまたぐ資料（観測の流れ、運用のルール、トラブルシューティング、障害情報、データの取得、解析、訓練）の所在と一行の要点、問い合わせの窓口（役割と経路）を、利用者の段階の順に並べる。確認日と、各ページの最終更新日を書く。
- **書かないもの：** 手順、締切、料金、性能の値は写さない（正本は一つ）。窓口は役割と経路だけを書き、メールアドレスや招待の URL は写さず、それが書かれている正本のページを指す。接続先と、非公開のページの URL は書かない。
- **装置ごとの資料は台帳の `docs` に書く。** 受信機、分光計、アンテナ、データの保管、解析のソフトウェアのページの URL を、各運用リポジトリの台帳に書く（0006 の、装置の情報は運用リポジトリに置く決まりのとおり）。`users/` からは台帳の `id` を指す。
- **一次資料の食い違いと欠けを、`users/` に書いておく。** 占有期間が資料によって違う、計算機チームの宛先がない、などの点を書き、ウェブサイトの担当が直したら消す。
- **非公開の一覧：** 観測者向けの非公開の資料（リモート観測のマニュアル、緊急連絡先、データの取得の方法、VPN の手順）の行を足し、正本の場所をシステムの粒度で書く。「装置の制御や情報セキュリティに関わる詳細」と「未公開の観測データ」の正本の場所を、公開資料と台帳から書ける範囲で埋める。

## 比較した選択肢

- **`mission/` に足す：** `mission/` には、利用要領や運用のルールの所在がすでにある。しかし `mission/` は目的と決まりを扱う区分で、観測の手順や窓口は性質が違う。利用者の段階の順に読める一枚にするほうが、Q6 と Q7 の読み手（提案者と観測者）に合う（仮説）。規程の所在は `mission/` に残し、`users/` からはそこを指す。
- **台帳の `docs` だけに書く：** 新しい場所は要らない。しかし窓口、観測の流れ、運用のルール、失った時間の扱いは、特定の装置に属さない。
- **手順の要約を文脈基盤に写す：** 文脈基盤だけで答えが完結する。しかし正本が二か所になり、ウェブサイトの更新とずれる。手順には制御の詳細も含まれる。
- **窓口のメールアドレスを写す：** 一度で届く。しかし宛先が変わったときに二か所を直す必要がある。役割と経路と、宛先が書かれたページを示せば、0010 と 0011 の満たし方に届く。
- **ウェブサイトの改修を待つ：** 一次資料の欠け（宛先がない、ページが古い）は残るが、索引は今の一次資料でも作れる。欠けは索引に書いて、改修の材料にする。

## 根拠とその区分

- **事実：** Q5・Q6・Q7 の欠けは、問い合わせの窓口と資料の所在に集まっていた（[2026-11-18-7](../questions/results/2026-11-18-7.md) の「文脈基盤の欠けの全体像」、[2026-11-18-8](../questions/results/2026-11-18-8.md) の「欠けの全体像」）。
- **事実：** 観測準備の流れ、望遠鏡運用のルール、積分時間の見積もり、受信機ごとのページ、ヘルプデスクの経路は、観測所のウェブサイトで公開されている（2026-11-19 に確認。所在は [users/](../users/README.md)）。
- **事実：** 公開資料が正本の情報は、所在と確認日を示せば満たしたとする（[0010](0010-上流の問いに観測の利用者の問いQ6を加える.md)）。公開方針で入れない情報は、正本の所在と役割の粒度の窓口を示せば満たしたとする（[0011](0011-上流の問いに観測者の支援の問いQ7を加える.md)）。
- **事実：** 同じ情報を二か所に書き写さない（[CONTRIBUTING.md](../CONTRIBUTING.md) の「正本は一つ」）。台帳の `docs` には、公開の資料は URL を書く（[assets/README.md](../assets/README.md) の項目の定義）。
- **事実：** 観測者向けの非公開の資料は、計算機グループの計算機とネットワークのシステムのページにあり、所内のネットワークか VPN からだけ読める（[観測準備](https://www.nro.nao.ac.jp/projects/45m/observations/)、[観測データ](https://www.nro.nao.ac.jp/projects/45m/data/)、2026-11-19 に確認）。
- **仮説：** 利用者は困ったとき、装置の名前ではなく段階（提案、準備、観測、トラブル、データ、解析）から資料を探す。段階の順の索引のほうが、台帳の `docs` だけより引きやすい。

# 上流の問い

文脈基盤の完成度を測る物差しです。目指す上流の支援を具体的な問いとして書き出し、定期的に AI に投げて、文脈基盤の根拠を示しながら答えられるかを確かめます。機械学習の評価用データセットと同じ役割です。

## 問いの集合

いまの版は第4版です。第1版（[0003](../decisions/0003-上流の問いの初版を定める.md)）の Q1〜Q4 に、外部の参加を測る問いとして、外部の開発者の Q5（第2版、[0009](../decisions/0009-上流の問いに外部の開発者の問いQ5を加える.md)）、観測の利用者の Q6（第3版、[0010](../decisions/0010-上流の問いに観測の利用者の問いQ6を加える.md)）、観測者の支援の Q7（第4版、[0011](../decisions/0011-上流の問いに観測者の支援の問いQ7を加える.md)）を加えました。Q1〜Q6 は加えたときから変えていません。

| 番号 | 問い | 主に要る区分 |
|---|---|---|
| Q1 | 観測所のシステムとソフトウェアを統合整理するなら、どこから手をつけるべきか | 資産、業務 |
| Q2 | 業務全体の中で、最も効果の大きい改善はどこか | 業務、数値 |
| Q3 | 今の装置と人員で、新たに始められる事業は何か | 使命、資産、業務、外部 |
| Q4 | 10年後の観測所のあるべき姿の選択肢は何か | 使命、外部、経緯 |
| Q5 | 外部の開発者が、45m 鏡への装置の持ち込みや、観測所での装置の開発を検討するとき、何を示せるか | 使命、資産、業務、経緯、外部 |
| Q6 | 45m 鏡での観測を検討している利用者が観測提案を作るとき、何を示せるか | 使命、資産、業務、数値、経緯 |
| Q7 | 45m 鏡で観測時間を割り当てられた観測者が、観測の準備から解析までを進め、途中のトラブルに対処するとき、何を示せるか | 使命、資産、業務、数値、経緯 |

## 答えの形と要る文脈

答えられたかどうかを判定するために、問いごとに、よい答えが含むべきものと、その根拠になる文脈を決めておきます。答えの形を満たし、その根拠を文脈基盤のファイルで示せたときに「答えられた」とします。

| 番号 | 答えの形 | 要る文脈 |
|---|---|---|
| Q1 | 統合・整理の候補（どのシステムやソフトウェアのまとまりか）と、着手の順序。順序の理由を、依存関係、保守の手間、担い手の数、更新の期限で示す | 資産：台帳（構成、依存関係、保守状況、使用年数、担当の役割）。業務：保守の手間と担い手の数。経緯：過去の更新や統合の検討 |
| Q2 | 改善の候補と、見込める効果（減らせる手間、下げられるリスク）、その前提。効果の大きい順に並べる | 業務：業務一覧（頻度、手間、属人度、単独で判断できる人が一人しかいない業務）。数値：稼働率、トラブルの統計。経緯：過去の改善の試み |
| Q3 | 事業の案ごとに、使う装置と人員、使命・規程・協定との整合、他の施設での類例、収支の見通し | 使命：中期計画、規程、協定。資産：装置の能力と空き。業務：人員の余力。外部：需要、他の施設の事例。数値：収支 |
| Q4 | 複数の選択肢と、それぞれの前提、要る資源、どの選択肢に進むかを分ける条件 | 使命：中期計画と国立天文台の将来計画。外部：学術コミュニティの将来計画、国のロードマップ、他の施設の動向。経緯：これまでの運用形態の変更とその理由。資産：主要な装置の寿命 |
| Q5 | 外部の開発者が読んで次に何をすればよいか分かる形で、次の10の要素を示す。(1) 前例（持ち込まれた装置とその後の経過）、(2) 観測所が提供するものとしないもの、(3) 観測所側の体制と引き受けの見込み、(4) 既存の装置との重なりと入れ替わり、(5) 望遠鏡の寿命、(6) 信号の取り合い（IF、分光計、時刻と周波数の基準）、(7) 機械と光学の取り合い（搭載の場所、重量、電源、冷却、ビーム伝送）、(8) 制御とソフトウェアの取り合い（観測制御、観測指示書の作成、データの形式）、(9) 手続き、審査、窓口、時期、(10) 費用。公開しない情報が要る要素は、非公開であることと問い合わせ先を示せれば満たしたとする | 使命：開発プログラム、利用要領、有料の望遠鏡時間、JSAC。資産：台帳と、取り合いの要約。業務：受け入れに関わる業務と人数。数値：料金、開発プログラムの件数。経緯：持ち込みの前例と審査。外部：他の施設の持ち込みの制度と料金 |
| Q6 | 利用者が読んで提案を書き始められる形で、次の14の要素を示す。(1) 公募の枠と種類、締切、提出の方法と書式、(2) 料金、(3) 利用の規程、(4) 使える受信機と分光計、提供の状態、同時観測の組み合わせ、いまの不具合や制約、(5) 受信機の性能（周波数帯、雑音温度、ビームサイズ、能率、偏波、ビーム数）、(6) 分光計の構成と、帯域と分解能の組み合わせ、(7) 観測のモードとその制約、(8) 積分時間の見積もりの方法、(9) 天候、停止の割合、観測シーズン、(10) 観測指示書の作成、(11) リモート観測、(12) データの取得と占有期間、(13) 解析の環境、(14) 初めての利用者の訓練、マニュアル、問い合わせの窓口。観測所の公開資料が正本で変わりうる情報（性能の数値、締切と書式など）は、正本の所在（該当する箇所へのリンク）と確認した日を示せれば満たしたとする。正本に書かれていないリスクは文脈基盤で示す | 使命：プロポーザルの募集、有料の望遠鏡時間、利用要領、運用のルール。資産：台帳の提供の状態と不具合、データシートの該当箇所への所在、観測指示書の作成と解析のツール、データの保管。業務：観測支援と共同利用の業務、問い合わせの窓口。数値：料金、停止の割合、応募と割り当ての件数。経緯：外部評価2023 の利用者の訓練についての指摘 |
| Q7 | 観測者（初めて 45m 鏡を使う大学院生を想定）が読んで次に何をすればよいか分かる形で、次の17の項目を示す。トラブルの場面：(A1) 国外からのリモート観測で画面が極端に遅い、(A2) 強風でアンテナが止まった、失った時間の扱い、(A3) ポインティングで電波源が受からない、オフセットが大きい、(A4) 分光計の一部のアレイでスペクトルが出ない、形がおかしい、(A5) H40 でシステム雑音温度が高い、(A6) 観測指示書の作成で 7BEE が選べない、(A7) 夜間に装置が止まり復帰できないときの連絡、(A8) データが見つからない、取得できない、(A9) OTF のマップに縞やベースラインのうねりが出た、(A10) 天候が悪いときに観測するかを誰がいつ何を基準に決めるか。準備から解析までの流れ：(B1) 採択から観測日まで（アカウント、リモート接続の準備、観測指示書、日程の通知）、(B2) 観測の開始（装置の状態の確認、較正、ポインティング、焦点）、(B3) 観測中の監視と判断、(B4) 観測の終了と引き継ぎ、(B5) データの取得（場所、形式、時期）、(B6) データ解析（ソフトの入手と導入、標準の手順、CASA への書き出し）、(B7) マニュアル、FAQ と問い合わせの窓口。○ は対処や手順、または正本の所在と問い合わせ先を示せたとき、△ は関係する事実だけを示せたとき、× は記録がないとき。A と B を分けて数える。公開方針で入れない情報（制御の手順、接続の方式、個人の連絡先）は、正本の所在（部署名やシステム名の粒度）と窓口（役割の粒度）を示せれば満たしたとする | 使命：望遠鏡運用のルール、利用要領、有料の望遠鏡時間の案内のうち停止した時間の扱い。資産：台帳の不具合と障害情報の所在、リモート観測、観測指示書の作成と解析のツール、データの保管。業務：観測支援、共同利用、観測アカウントの発行、問い合わせの窓口。数値：停止の割合。経緯：外部評価2023 の利用者の訓練についての指摘。非公開の一覧：観測者向けの非公開の手順書と連絡の一覧の正本の場所 |

問いの追加や変更は、上流の変更として扱います。判断記録を添えたプルリクエストで行ってください。番号は振り直さず、使わなくなった問いは「（廃止）」と記します。

## 確かめ方

1. AI に、このリポジトリの目録と関係するリポジトリを読ませたうえで、問いを投げます。
2. 結果を `results/YYYY-MM-DD.md` に記録します。書くのは、答えの要点、示された根拠とその区分、答えられなかった点、使った AI とその設定です。
3. 答えられなかった問いや、根拠が足りなかった箇所を、issue（雛形「上流の問いへの未回答」）に記録します。これが次に集める文脈になります。

最初に確かめるのは、資産の台帳の初版ができた時点です（[0001](../decisions/0001-文脈基盤と公開の進め方を採用する.md) の予測）。

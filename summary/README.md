## 全体の段階

- **フェーズ1（文脈基盤の整備）の立ち上げ中です。** ハブの骨組み、進め方の決まり、公開方針、最初の判断記録（0000〜0002）、Claude の入口がそろいました。判断記録はいま14件です（下記）（[0001](../decisions/0001-文脈基盤と公開の進め方を採用する.md)）。
- 最初の目標だった資産の台帳の初版は、ハブの `assets/` に置きました（0005）。その時点で上流の問いの最初の試行を行いました（下記）。
- 資産の情報の正本を、装置群ごとの運用リポジトリに移しました（0006）。2026-11-18 に、9つの運用リポジトリ（分光計、受信機、アンテナ、観測制御、データの保管、利用者向けのツール、IF 系、連続波、標準時計）を作り、聞き取りで台帳の未記入を埋めました。ハブの仮置きの台帳は空になり、ハブには装置の情報を置いていません。続けて、数値の区分を `nro-metrics` で始め（0007）、業務の区分を `nro-work` で始めました（0008、2026-11 の月次マージからの最初の書き出し）。
- フェーズ2（運営の仕組み）には、上流の問いに根拠を示して答えられるようになり、判断記録が蓄積したときに移ります。

## 上流の問い

- [questions/](../questions/README.md) に Q1〜Q7 と、問いごとの答えの形と要る文脈があります。問いの集合は [0003](../decisions/0003-上流の問いの初版を定める.md) で初版（Q1〜Q4）として確定し、[0009](../decisions/0009-上流の問いに外部の開発者の問いQ5を加える.md)で外部の開発者の問い Q5 を加えて第2版に、[0010](../decisions/0010-上流の問いに観測の利用者の問いQ6を加える.md)で観測の利用者の問い Q6 を加えて第3版に、[0011](../decisions/0011-上流の問いに観測者の支援の問いQ7を加える.md)で観測者の支援の問い Q7 を加えて第4版にしました。
- 2026-11-17 に事前の試行を行いました（[結果](../questions/results/2026-11-17.md)）。Q1・Q2 は答えられない、Q3・Q4 は部分的でした。
- 2026-11-18 に、資産の台帳の初版を取り込んだ時点で最初の試行を行いました（[結果](../questions/results/2026-11-18.md)）。Q1・Q3・Q4 は部分的、Q2 は答えられない。未回答の点は issue #16〜#19 にあります。
- 同じ日に、運用リポジトリ3つで聞き取りを終えた時点で2回目の試行を行いました（[結果](../questions/results/2026-11-18-2.md)）。判定は変わらず、Q1 の順序の理由と Q4 の分かれ目の条件が具体的になりました。最大の欠けは業務と数値です。
- 同じ日に、数値の区分（38系列）を入れた時点で3回目の試行を行いました（[結果](../questions/results/2026-11-18-3.md)）。三段階の判定は変わらず、答えの形の要素ごとの判定は 21要素中 9.0 → 12.5 に増えました。Q3 の収支と Q4 の分かれ目の条件が埋まりました。最大の欠けは業務と、過去の検討の経緯です。
- 同じ日に、業務の区分（58業務）を入れた時点で4回目の試行を行いました（[結果](../questions/results/2026-11-18-4.md)）。**Q2 が初めて「部分的」になりました。** 要素ごとの判定は 21要素中 16.0。次の欠けは、判断レベルの記入、手間の量、過去の検討の経緯です。
- 同じ日に、Q1〜Q4 とは別の候補の問いとして、「受信機を新しく開発している外部の開発者が、持ち込みを検討するときに必要な情報を示せるか」を試しました（[結果](../questions/results/2026-11-18-5.md)）。判定は部分的で、10要素中 6.5。前例、観測所側の体制、装置の見通しは示せる一方、手続きと審査、搭載の物理的な条件、費用はほとんど記録がありません。この試行を Q5 の事前の試行として扱います（0009）。
- 同じ日に、もう一つの候補の問いとして、「45m 鏡での観測を検討している利用者に、観測提案を作るのに要る情報を示せるか」を試しました（[結果](../questions/results/2026-11-18-6.md)）。判定は部分的で、14要素中 7.5。使える受信機、料金、リモート観測、解析の環境、装置のリスクは示せる一方、受信機と分光計の性能の数値、積分時間の見積もり、締切と提出の手続き、訓練の資料は記録がありません。この試行を Q6 の事前の試行として扱います（0010）。
- 同じ日に、第3版（0010）で Q1〜Q6 をすべて回しました（[結果](../questions/results/2026-11-18-7.md)）。**すべて部分的。** Q1〜Q4 は 21要素中 16.5 で4回目と変わらず（4回目の 16.0 は数え違い）。Q5 は 10要素中 7.5、Q6 は 14要素中 9.0 で、事前の試行との差は判定の基準と満たし方の変更によるもの。次の欠けは、手間の量と過去の検討（Q1〜Q4）、手続き・仕様・窓口（Q5・Q6）。食い違いを新しく15件見つけました。
- 同じ日に、Q6 の後の段階を扱う候補の問いとして、「観測時間を割り当てられた観測者が、準備から解析までを進め、途中のトラブルに対処するのに要る情報を示せるか」を試しました（[結果](../questions/results/2026-11-18-8.md)）。判定は部分的で、17項目中 6.0、○はなし。装置のいまの不具合は出典つきで示せる一方、問い合わせの窓口と観測者向けのマニュアルの所在、天候と風の判断、観測の終了と引き継ぎは記録がありません。この試行を Q7 の事前の試行として扱います（0011）。
- 2026-11-19 に、利用者と観測者の資料と窓口の索引（0012）を入れた時点で、Q5〜Q7 を回しました（[結果](../questions/results/2026-11-19.md)）。**三つとも部分的のまま、点は大きく上がりました。** Q5 は 10要素中 7.5 → 8.0、Q6 は 14要素中 9.0 → 13.5、Q7 は 17項目中 6.0 → 12.5（Q7 は最初の正式な試行）。上がった項目はすべて公開資料の所在によるもので、前回まで「記録がない」とした多くは一次資料にすでにありました。残る欠けは、一次資料そのものにないもの（天候の判断の基準、OTF の縞、症状ごとの切り分け、焦点、FAQ、観測シーズン）と、Q5 の取り合いの仕様と審査の中身です。

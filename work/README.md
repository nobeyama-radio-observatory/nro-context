# 業務

7つの区分のうち「業務」の公開の項目の定義と、公開用の書き出しの手順を置きます。業務一覧そのものの正本は、業務のリポジトリ `nro-work` です（[0008](../decisions/0008-業務一覧を月次マージから集計して公開する.md)）。

項目の定義の変更は、上流の変更として扱います。判断記録を添えたプルリクエストで行ってください。

## 材料と流れ

```
各自の worklog（非公開）
  → 月次マージ（マージ担当。worklog のあるマシンで）
  → 共有の業務グループのファイル（非公開。個人名を含む）
  → 公開用の書き出し（このページの項目と確認の項目に沿って、同じマシンで作る）
  → nro-work へのプルリクエスト（同じマシンから出す）
```

- **非公開の材料は、worklog のあるマシンから持ち出しません。** 共有の業務グループのファイルには、関係者の欄に個人名が入っています（[非公開の一覧](../policy/non-public.md)）。持ち出すのは、公開用の書き出しだけです。
- 書き出しは、worklog のスキルの「月次マージ」の最後の手順として行います（[skills/worklog](../skills/worklog/SKILL.md)）。

## 置き方

- `nro-work` の `groups/<業務グループ>.yaml` に、業務グループごとに1ファイルで置きます。業務グループは、worklog のタグ辞書の第1階層です。
- 書き出しのたびに、ファイルの冒頭の `as_of`（集計した月）を更新します。前の版は Git の履歴に残ります。

## 項目

ファイルの冒頭：

| 項目 | 必須 | 内容 |
|---|---|---|
| `group` | 必須 | 業務グループの名前（タグの第1階層） |
| `as_of` | 必須 | 集計した月（`YYYY-MM`） |
| `source` | 必須 | 「worklog の月次マージ（YYYY-MM）」。非公開の材料なので、場所は書かない |
| `tasks` | 必須 | 業務の列。次の項目を持つ |

業務ごと（`tasks[]`）：

| 項目 | 必須 | 内容 |
|---|---|---|
| `tag` | 必須 | worklog のタグ（`#業務グループ/個別業務`）。公開できない語を含む場合は言い換える（下の確認の項目） |
| `name` | 必須 | 業務名 |
| `category` | 必須 | 分類（worklog の業務一覧の「分類」。装置、開発、事務、広報など） |
| `frequency` | 必須 | 頻度（随時、週数回、月1回、年1回、観測期前など） |
| `timing` | 任意 | 時期・期限（観測期、3月など） |
| `docs` | 必須 | 手順や資料の有無。`あり（公開）`、`あり（所内）`、`一部`、`なし` のいずれか。公開のものは URL を添える。所内の場所は書かない |
| `people` | 必須 | 関わっている人の数 |
| `judges` | 必須 | 単独で判断できる人の数（判断レベル L4 以上の人数） |
| `learners` | 必須 | 経験を積んでいる人の数（判断レベル L2〜L3 の人数） |
| `concentration` | 必須 | 属人度。`高`、`中`、`低` |
| `status` | 必須 | `現行` または `終了`。終了した業務も消さない |
| `assets` | 任意 | 関係する資産の `id`（[assets/](../assets/README.md) の索引で引ける） |
| `note` | 任意 | 補足 |

## 書き出しの前の確認の項目

公開用の書き出しを作るたびに、次をすべて確かめます。一つでも当てはまれば、書き出しを直してから PR を出します。

1. **個人名がない。** 関係者の欄は人数にしただけで、名前、イニシャル、「本人」「自分」などの語が残っていない。
2. **個人の判断レベルがない。** 判断レベルは `judges`（L4 以上の人数）と `learners`（L2〜L3 の人数）だけ。誰がどの段階かは書かない。
3. **人数から個人を当てられない形になっている。** 関わる人が1〜2人の業務でも、人数は書いてよい（業務単位の集計、[公開方針](../policy/disclosure.md)）。ただし `note` に、その人を当てられる記述（役職、経歴、在籍期間など）を書かない。
4. **装置の制御や情報セキュリティの詳細がない。** 業務名とタグに、接続先、アカウント、ネットワーク構成、制御の手順が入っていない。入っている場合は「計算機の保守」のように一般的な語に言い換える。
5. **契約の中身がない。** 外部の事業者の名前と契約の条件を書かない。
6. **手順や資料の在りかに、所内の場所がない。** 所内のパス、共有ストレージの場所は `あり（所内）` とだけ書く。
7. **未公開の観測データ、個別の対応の詳細（トラブル記録の中身）がない。**

迷うものは書き出しから外し、issue で相談します。

## 手間の量について

[公開方針](../policy/disclosure.md)は、業務の区分に「手間の量」を含めています。しかし、worklog は記録を続けやすくするために作業時間を聞かない決まりです。そのため、当面は手間の量を `frequency`（頻度）と `timing`（時期）で表します。作業時間で表すかどうかは、運用しながら判断記録で決めます。
